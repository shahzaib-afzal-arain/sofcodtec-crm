# Settings audit and configuration contract

Original Settings has a category selector, four static connector cards, generic uncontrolled inputs and an in-memory saved boolean. It has no persisted Settings namespace, validation, provider-specific configuration, actual health service or credential service. Reference values (12/14, 99.98%, heartbeats, quota use, Chromium cluster) are illustrations; they are removed from operational status reporting. Existing routes, global design tokens and other screens remain unchanged.

Only `crm-settings-state` version 1 is owned here: revision, config and history. Missing storage uses in-memory defaults without writing. No existing Settings persistence was found; unsupported/unknown legacy versions and unknown fields are blocked and preserved, never guessed/migrated or reset automatically. Schema whitelists every non-secret section and field. Credential/token/password fields cannot enter saved config/history. History stores changed field paths, not field values. Malformed raw storage requires restoring a valid backup outside this screen; no destructive recovery button exists.

Configuration is an intent draft, not a provider capability guarantee, live connection or application-wide enforcement. All connectors default disabled. Locally configured counts require a saved enabled intent; credential/testing/rotation/sync/webhook-ping operations are disabled with backend explanations. No network requests are issued. Endpoint metadata requires HTTPS without credentials/query/fragment; never enter secrets. Credentials/signing keys are never accepted by editable forms and never stored/exported/logged.

Save All validates the entire draft, reports field errors, checks the reviewed raw snapshot for cross-tab conflicts, writes one namespace and then updates the saved baseline. Failed/stale writes retain the draft. Duplicate/clean saves perform no write. Category/connector switching preserves drafts. Explicit discard/reload/reset requires confirmation; beforeunload warns for dirty state. Reset changes the draft only, requiring a later save. Reset is unavailable when the persisted baseline cannot be read safely.

Company details default blank because no verified business profile exists. Currency/timezone/format/pagination preferences are local plans only; no other records are converted or modified. Notifications, SLA, crawler and retention preferences do not deliver messages, change deadlines, crawl, purge, archive or back up data. Robots compliance is mandatory in this planner.

Team `crm-team-state` is read-only via its existing validator. Only role/rule counts and assignment-rule metadata are displayed. No member secrets/notes are exported. Source warnings do not overwrite Team. Storage measurement reads only this Settings namespace and reports approximate UTF-16 bytes, not server storage or browser quota. Audit settings reflect the actual Audit Center categories (mobile, checkout, scripts and payments), not connected Google/Cloudflare services.
