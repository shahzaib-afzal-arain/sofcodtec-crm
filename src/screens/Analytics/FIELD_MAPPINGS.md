# Analytics source contract audit

Analytics is read-only. Missing namespaces are empty; source helpers that seed fixtures are never used to fabricate report rows. Original samples and explicit simulation records are excluded. No Analytics targets or financial assumptions are written.

| Module / namespace | Actual mapping | Reporting basis / limitation |
|---|---|---|
| Leads / crm-added-leads (array) | id, prospectId, name, domain, owner, source, platform, stage, createdAt when present | Lead creation cohort. Manual LeadForm and Lead Generation currently do not save createdAt; missing dates are excluded, never replaced. Imported sample prospects (tech: Demo prospect / explicit sample notes) are excluded. |
| Verification / crm-verification-state (v1 records map) | per-key status, dns, confidence, approved, rejected | No verification event timestamps. loadVerification intentionally keeps non-simulated users pending/unverified. No actual verified conversion metric is asserted. |
| Audit / crm-audit-center-state (v1 records) | id, leadId, source, status, timestamp, result | Audit process generates illustrative results even for manual targets. Runs are disclosed as simulated, not counted as genuine completed audits. |
| Opportunities / crm-opportunity-sheets-state (v1 records) | id, leadId, auditId, platform, status, source, updatedAt | Current opportunity snapshots; updatedAt is not creation/qualification history. Demo findings/intakes excluded. Period-linked segment counts require an explicit persisted createdAt, otherwise unavailable. |
| Pipeline / crm-sales-pipeline-state (v1 records) | id, leadId, owner, stage, value, probability, probabilityMode, expectedClose, closedOn, source | Closed Won uses authored date-only closedOn. Open/weighted values are projected expected-close months, not historic pipeline snapshots. Module's value contract is USD; an explicit currency, if present, is kept separate. Missing probability omits weighted value. Local won deal estimates are never recognized revenue/ARR. No stage history or createdAt in current schema. |
| Activities / crm-activities-state (v1 records) | id, leadId, accountId, channel, outcome, direction, timestamp, createdAt, relatedActivityId | Logged interactions use timestamp; linked lead milestones require ordered dated proof. Sent/Reply outcomes require explicit user-confirmed outcomes. Task completion has no immutable completedAt; completion period is unavailable. |
| Follow-ups / crm-followups-state (v1 records) | id, leadId, activityId, sourceActivityId, createdAt, dueAt/dueDay, status, completedAt | Created tasks by createdAt; completion by completedAt; overdue at selected period end (capped at now), among tasks created by that cutoff. Imported Activities tasks are deduplicated by activityId. Historical status snapshots are unavailable, so overdue is explicitly a current-state deadline check, not reconstructed history. |
| Meetings / crm-meetings-state (v1 records) | id, leadId, activityId, followUpId, startAt, status, completedAt, source | Scheduled counts by startAt, cancelled excluded. Completed telemetry by explicit completedAt. Original four undated samples excluded. Activity-channel meeting logs remain a separate disclosed log count; not added to independent Meetings totals. |
| Proposals / crm-proposals-state (v1 records) | id, leadId, dealId, opportunityId, owner, createdAt, status, version, history | Actual independent proposals counted by createdAt; original candidate leads and static illustration are not proposals. Proposal amounts never enter deal values or revenue. |

## Identity and reporting rules

- Duplicate IDs (and ambiguous duplicate source prospect IDs for leads) are quarantined rather than arbitrarily choosing one record. Repeated module references resolve to one canonical persisted lead ID. Domain fallback is allowed only when exactly one persisted lead owns that normalized domain. Broken/ambiguous references are disclosed.
- Qualification is the current explicit Qualified state of a dated lead cohort or an explicitly Qualified linked deal; no qualification transition date or historic qualification change is inferred.
- Funnel stages are distinct linked milestones inside the lead-creation cohort. Percent-of-cohort uses that cohort only. Previous-stage conversion/velocity requires ordered event timestamps; missing verification/audit histories and date-only won records do not receive invented velocities.
- Acquisition and technology use persisted lead source/platform fields (CRM classifications, not audit detections or note keywords). Unknown attributes are shown as Unknown. Won-value attribution requires a reliable lead link; currencies remain separate.
- Representative names match exactly. Contact names are not substituted for reps; aliases are not guessed. Representative filtering uses each record's actual owner, and linked attribution uses the filtered cohort only.
- All report calendar dates use Asia/Karachi. ISO timestamps require an explicit timezone; date-only pipeline close dates are retained as authored calendar dates. Future history/creation events and invalid dates are excluded. Equivalent previous periods have the same number of calendar days. Growth needs complete dated coverage and a positive prior baseline.
- No configured quota, revenue-target or recognized-recurring-revenue contract exists in the inspected modules. Quotas, revenue targets and ARR remain unavailable. No fictional configuration namespace is assumed.

## Visual correction / separate preview

- Sidebar `All Leads` badge is the literal `3.4k` in `src/components/layout/Sidebar.jsx`; it does not read storage. Analytics reads the same `crm-added-leads` namespace used by saved leads, but counts an owner-filtered, dated creation cohort. Undated/source sample exclusions are disclosed in coverage; no calculation was changed to reproduce the badge.
- `demoData.js` constructs a separate deterministic illustrative report. It uses no source storage and writes nothing. Actual mode remains the default on each mount. Period length and representative affect preview figures; this is disclosed as illustration rather than historical reporting.
- Preview-specific monthly targets and quotas exist only in that report, never in the actual engine. CSV branding/filename and printable report identify Demo Preview. Actual ARR, quotas and targets remain unavailable under the existing data contract.
- KPI definitions remain in native titles and expandable reporting information; compact visible captions replace repeated paragraphs. Empty funnel/financial panels use a single explanatory state instead of blank stage bars and repeated empty totals.
